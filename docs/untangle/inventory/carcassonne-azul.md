## Cross-game patterns noticed
- Each game re-implements the same 8-bit skin wiring: `gameSkin`/`setGameSkin` + lazy `import('./pixel.css')` + lazy sound pack + a `pixelReady` flag. Azul Board 99-113 and Carcassonne Board 113-130 are near-copies. The classic-vs-pixel sound facade exists as `ceramicAudio` (Azul `effects.ts:18-61`), `audio` object (Carcassonne `Board.svelte:131-153`), and likely other `pixel/sound.ts` packs in other games. Candidate for one shared helper in `@board-games/shared/ui/pixel`.
- Both `pixel/sound.ts` files wrap `createAudio()` with their own `mute`/`stop`/`close` and a private `timers`/`setTimeout` scheme. Azul cancels delayed ZzFX cues; Carcassonne does not (`pixel/sound.ts:62`). `tableAudio` (Carcassonne `effects.ts`) and `ceramicAudio` (Azul `effects.ts`) are siblings.
- Presentation gating: Azul `RevisionGate`; Carcassonne local `EventGate` (effects.ts:110); Codenames/Little Secret `eventGate()`. `docs/workflow.md` lists only `RevisionGate` and `eventGate()`.
- Preferences: Azul one JSON key `azul-preferences` (`readJson`/`write`); Carcassonne two string keys (`read`/`write`, 'on'/'off'). Skin via the shared store in both.
- `Board.svelte` prop contract differs per game and is not typed anywhere shared: Azul takes `pending/errorCode/canRematch/rematch/rulesContent/canConfigure(unused)`, Carcassonne takes `canConfigure(used)/settingsContent` and ignores the rest; Little Secret and Codenames take `canConfigure` too. The room page passes one superset to all (`room/[id]/+page.svelte:190-210`). Candidate: one `BoardProps` type in shared.
- Practice routes (`apps/web/src/routes/practice/*/+page.svelte`) all repeat: `onMount` + `gameClients[...]`, a language `<select>`, `:global(body:has(.<x>-practice) .site-header) { display: none }`, the same alert `<p>` style, and `try { send } catch { error = m.<game>_error() }`. Pages differ in seat tracking, `{#key locale}`, `setLocale` options and how scenario labels are looked up. Candidate: one practice shell component.
- Rules error convention: Azul `AZUL_*` codes -> collapsed to one message in the room page; Carcassonne plain English; Codenames `cn_error`; Domino `DOMINO_ACTION`; UNO 'Invalid action.'. No shared type for "error that is a message key".
- Both games hide the app shell using `body:has(.<table-class>)` global selectors (Carcassonne Board 2095-2096; the practice pages for all games).
- Both `practice.ts` use `seeded(...)` from game-core with a hard-coded seed (Azul 492/789; Carcassonne 3109/9222026) and expose `practice(scenario)` with `{actor, view, send}`; Azul adds `players`, Carcassonne `state`. A shared `practiceGame` interface would remove page differences.
- The `data-<game>-location` / `[data-location],[data-region]` DOM-attribute protocols are used by Azul (measuring flights) and Carcassonne (hit testing); similar "measure-by-attribute" flight logic may exist in other games (Sushi Go Party, UNO).
- Dead-ID guard `#az-pixel` specificity hack in Azul vs `.carc-table.cc-pixel` double-class in Carcassonne for the same cascade problem — two different fixes; check other `pixel.css` files for a third.
