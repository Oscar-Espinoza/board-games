## Cross-game patterns noticed

What each Board re-implements around them is the policy layer: skin lazy-load, preference persistence, settings dialog, skin chooser. Per game (7 Board.svelte games; domino differs, see below):

- Skin lazy-load `$effect` (`if (skin === 'pixel' && !pixelReady) import('./pixel.css') [+ sound]`) copied in all 7 Boards, along with `const pixel = $derived(skin === 'pixel' && pixelReady)`. Only the set of things imported varies (css only: catan, codenames, sgp; css+sound: uno, azul, little-secret; css+sound+art: carcassonne).
- Skin chooser `<fieldset class="skin-choice">` with radio group named `<game>-skin` and its `.skin-choice` CSS block copied in 7 Boards (grep `skin-choice`: uno 1437, catan 2726, carcassonne 3072, azul 1703, codenames, sgp 1746, ls 1140). Settings `<dialog>` with backdrop-click close copied in 6 (uno `:627-630`, etc.).
- Preference persistence: 3 key schemes (`game:key` separate keys: uno, catan, carcassonne, domino; `game:preferences` JSON: codenames, sgp, ls; `azul-preferences` with a dash: azul) and 3 value encodings ('on'/'off', 'true'/'false', JSON booleans). `sound` + `motion/reduced` + `volume` are the same three settings everywhere. A shared `usePreferences(game, defaults)` returning `$state` plus persistence would replace ~7 hand-written read/write blocks. Keys are written under different prefixes than `board-games:*` used by `skin`, `theme`, `name`, `room:<id>`, so there are 4 namespaces.
- `pixel/sound.ts` in uno, catan, carcassonne, azul, little-secret, sushi-go-party, domino (7 of 8 games) each define the same `note(from, delay, duration, volume, type='square', to)` helper wrapping `audio.tone({..., attack: 0.002})` (grep `attack: 0.002`; sgp scales volume by `level`). Likewise `tune/run(notes, step)` helpers in uno, ls, sgp. Candidate: `chiptuneKit(audio)` in `packages/shared/src/ui/pixel/`. Meanwhile `playChiptune` (ZzFX) is used by only codenames, catan, azul, uno, ls, sgp for the second sound path; carcassonne uses `buildSamples` directly (`pixel/sound.ts:60`) so the cache in `zzfx.ts:277` is duplicated there.
- `effects.ts`/`motion.ts` in codenames (28 lines) and little-secret (29 lines) are near-identical thin wrappers (`soundEffects()` creating `createAudio`, `unlock: audio.unlock`, `cancel: audio.stop`, `dispose: audio.close`, `play(volume, cue)` with the same clamp and `* 0.08`, `attack: 0.015`); sgp `effects.ts:18` and carcassonne `effects.ts:106` also expose `close: audio.close`. Return-object naming differs per game (`dispose`/`close`/`cancel`). Catan has a 605-line `effects.ts`; azul 197, uno `motion.ts` 258.
- sgp creates two `createAudio()` instances (`effects.ts` and `pixel/sound.ts:~17`), carcassonne two (`effects.ts`, `pixel/sound.ts`), because the classic and pixel packs each own a context; unlock must be called on both, hence `Board.svelte:192` `(skin === 'pixel' ? chip : audio).unlock()` in sgp and the facade in carcassonne. Other games share one instance (`audio.audio` passed to chiptune). Two patterns for one problem.
- Effect gating: RevisionGate (catan, azul, domino), eventGate (codenames, little-secret, domino?), carcassonne has its own `EventGate` class in `Board.svelte` (`gate = new EventGate()` ~:112); uno and sgp rely on their own mechanisms (check `uno/src/motion.ts`, `sushi-go-party/src/Board.svelte` `clearPresentation`/`cursor.reset`). Four mechanisms for "don't replay effects on reconnect".
- Pixel context: `games/little-secret/src/pixel/context.ts` and `games/sushi-go-party/src/pixel/context.ts` are identical files (`providePixel`/`usePixel`); catan uses an inline `setContext('catan:pixel')`; azul uses a Symbol in `palette.ts`.
- Per-game "pixel/" skins in `docs/*-pixel.md`: seven separate docs for the same kit.
