# Azul Table Light: implementation milestones

These are dependent milestones in one presentation migration, not nine independently shippable restyles. Existing user changes must be preserved. Public rules types, `DRAFT`, projections, accepted-event unions, networking, retry policy and eager catalog metadata stay unchanged.

1. Correct the specification, ADR 017 and repository instructions together. Extract the game palette while preserving the circular first-player marker and the independent catalog cover palette. Establish scoped materials, original props and licensed self-hosted fonts.
2. Build width-driven full boards, explicitly noninteractive compact boards, exact scores and the decorative rail. Establish the fixed viewport composition: supply/board columns on desktop, compact board overview and selection dialogs on smaller or shorter screens.
3. Implement collision-checked rings, the phone factory chooser and disjoint scattered centre groups. Preserve confirmation, explanations, keyboard focus and nonzero canonical anchors; exclude inspection copies from measurement.
4. Add the pure accepted-snapshot timeline, reconstructed final-draft slots, staged points/loss/bonuses, cleanup, separate marker return and delayed refill. Mount real tile artwork in body-level flights. Preserve revision eligibility and the existing audio system.
5. Add conserved practice fixtures and meaningful geometry/timeline/browser tests. Build before Playwright, inspect screenshots and motion, and update evidence with actual outcomes.

Validation: `bun run check`, `bun run test`, `bun run build`, affected Chromium and WebKit browser suites, and `bun run format:check`. Browser journeys cover phone picker and desktop direct play, centre keyboard controls, confirmation, inspection/focus, English/Spanish, silent audio fallback and multiplayer acceptance/reconnect. Assert unique measurable table anchors, flight endpoints/scales and cancellation, including when a dialog is open. Inspect new captures against preserved before-images and the corrected design.

The browser suite captures screenshots; it does not automatically compare screenshot baselines. Do not claim “no snapshot differences” as an automated guarantee. Physical Safari, actual device touch/audio and fluent Spanish review remain unverified until performed.

New sound voices, gray walls, expansions, bots, unrelated catalog/global typography changes and optional extensions are outside this work.
